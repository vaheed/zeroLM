# Claims and Limitations

## What is claimed (Phases 0-6)
- The repository defines, and CI enforces, what is hand-authored, what may be learned online, and what is prohibited.
- A CPU engine exists: deterministic kernels, four recurrent cells at equal parameter budgets, fixed-size exactly-resumable session state, measured at initialization. The GRU core was selected by a documented, reproducible score.
- Any byte sequence is accepted from the first run (no OOV, malformed UTF-8 located not rejected). Initialization is deterministic and pinned by SHA-256; no tokenizer or embedding asset exists.
- The teaching protocol is observable and traced, and a session provably leaves weights unchanged.
- Baseline reports record commit, clean-tree status, and toolchain; `zerolm-baseline check` rejects dirty or missing provenance.
- Phase 4: after one chronological pass over 40,000 generated bytes, a local delta rule on the readout layer predicts unseen sentences and unseen word combinations at about 2.3 bits/byte (BPB, bits per byte), against 8.0 for the same untrained architecture and 4.2 for a byte-frequency baseline (3 seeds, a floor frozen before the main run). A Hebbian rule with no error signal also clears the floor (about 3.3 BPB). Every update is logged and checked against the stream. See `docs/online-learning.md`.
- Phase 5: facts written through the live API persist across process restarts only as tensors in the model checkpoint, and are answered by an attention read over those tensors. On 3 seeds x 1,200 generated facts (with contradictions, supersessions, and deletions), after a restart: exact-key recall and precision 1.000; non-trivial paraphrase recall 0.973 and precision 0.993; 0.6% of negative queries answered. Memory writes leave every core tensor byte-identical; corrupt or interrupted checkpoints fall back to the last valid one; zeroing or permuting memory tensors drops recall to 0. Gates were frozen from pilot seeds. See `docs/memory-format.md`.
- Phase 6: statements of a bounded language are stored as bound role-filler phasor vectors in a tensor memory, and new questions are answered by eight controlled operators (class inclusion, transitivity, inheritance with exceptions, comparison, arithmetic by number binding, temporal order, negation, conditionals) built from vector probes, unbinding, and cleanup. On 3 seeds plus a hidden seed (about 525 questions each, 20 categories), answers agree with a symbolic reference on every question; a verbatim-lookup baseline gets 0% of the derived questions. Removing one proof premise changes answers exactly as the reference says (40/40 per seed), the reported premises alone reproduce each answer, and disabling any operator or the binding, discourse-state, or retrieval pathway removes exactly the inferences that depend on it. See `docs/reasoning.md`.

- Phase 7 (in progress, not complete): a neural ISA (instruction set architecture: the project's fixed list of tensor operations, see `docs/neural-isa.md`: matvec, gate, norm, bind, top-k, hash_rows, delta_write, step) runs programs compiled by `zerolm-wsp` (WSP = weight-space programming) from typed circuit specs in `model/prog/` (output hashes pinned; patches apply and revert to the original hash). Phase 5 semantic retrieval now runs only as the compiled `memory-read` program: the frozen Phase 5 gate passes unchanged through it on 3 seeds, an independent reference interpreter reproduces all 8,700 gate queries per seed bit for bit from the exported program bundle, and zeroing a circuit block removes exactly what it carries (verification: exact answers kept, every negative accepted; attention, selection, or cleanup: recall 0). See `docs/neural-isa.md`.

## What is not claimed
- The Phase 4 learner is weak: a byte trigram baseline beats it by about 1 BPB. Only the readout learns (on frozen random GRU features), on a tiny generated language of about 50 words. It shows online acquisition, not competitive language modeling and not English understanding.
- On a softmax readout, the delta rule equals one single-layer cross-entropy gradient step. It is local (no backpropagation through layers or time) but not gradient-free in a strict sense. The online-BPTT (backpropagation through time) control was not run.
- Catastrophic forgetting in the Phase 4 learner and long streams are unmeasured. Phases 7-11 are unimplemented.
- Phase 5 memory is slot-addressed storage with a programmed, not learned, retrieval computation. Its key encoder is a frozen bag of hashed byte trigrams: it ignores word order and has no synonymy. The facts are generated pseudo-word triples. It shows persistent weight-resident storage and retrieval, not understanding, reasoning, or memory learned from experience. W_FAST is small (about 0.75 recall at 32 associations). Each save rewrites a 24 MB checkpoint (about 1 s). Memory does not yet influence next-byte prediction.
- Phase 6 reasoning is programmed, not learned: the grammar and every operator's control flow are hand-written, and agreement with the symbolic reference is by construction. The test language is bounded with pseudo-word content; it is not open-domain understanding. Exclusion is directional, there is no modus tollens, and "it" means only the most recent subject. The reasoner is not yet connected to the Phase 4 learner or to generation.
- `zerolm run` serves `teach`/`ask`/`forget` from a session-local ledger, not from model memory. `zerolm memory --dir DIR` serves them from weight-resident memory. Neither involves understanding English.
- Bake-off metrics are initialization-time capacity measurements, not language ability, memory capacity, or learning evidence.
- No capability, benchmark score, or "human-level" claim is made. The roadmap revision 2 language-model levels (L1-L4) and the 1.0 target (L3) are goals, not results; the current system is Level L0.
- Uniform execution (constitution invariant 10) is met for Phase 5 semantic queries, and in Phase 6 only for the graph search (C5 decodes the relation memory, C6 computes reachability and shortest proofs; the Phase 6 gate passes unchanged). Still Rust control flow: the query text encoder (word split and trigram hashing on the host), write-time bookkeeping (slot choice, status, supersession; same-key detection now uses the circuit's output), W_FAST recall cleanup, and the rest of Phase 6: the parser and each operator's decision logic (inheritance levels, negation edges, conditional chaining, count arithmetic). The memory-read circuit is a hand-compiled algorithm, not learned, and has not been through the byte-permutation test. With the circuit and its reference-parity and ablation checks, the Phase 5 gate takes about 7 minutes instead of about 1, and a query takes about 0.9 ms (p50).
- Memory is finite; capacity and interference will be measured, not assumed.
- The static scan detects obvious pretrained artifacts and download calls; it cannot prove the absence of every hidden data source.
- Code and data from the removed v0.2 / ZeroLM Next experiments live only in git history; no results from them carry over.
