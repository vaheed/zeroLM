# ZeroLM Research Constitution

Status: in force from the start of the project. Machine-checked by `zerolm-audit` against
`research/manifest/*.json` and `model/specs/weight-groups.json`.

**Definition.** ZeroLM means *zero offline pretraining; online learning is allowed.*
The earlier "zero-training / no learning" wording belonged to the removed v0.2
and ZeroLM Next experiments and no longer applies.

## Terms

| Term | Meaning |
|---|---|
| Seed prior | Human-authored structure or constant present before any input. Listed in `seed-knowledge.json`; never derived from a corpus. |
| Online observation | One event of the chronological input stream, processed once, in order. |
| Feedback | A signal tied to an observation: the observed next byte, a user correction, a deterministic environment outcome, or an independently validated signal. |
| Memory write | Store of a key/value association into persistent memory tensors. |
| Local plasticity update | Bounded local rule (e.g. normalized delta rule) changing fast weights. No global gradient. |
| Online gradient update | One optimizer step of truncated backpropagation through time on a window of the chronological stream, scored before it is applied. Allowed in the mainline since 2026-11-26 (invariant 4). |
| WSP (weight-space programming) patch | Versioned, attributable, reversible weight edit, validated against frozen regression suites before acceptance. |
| Training | Any parameter change from a corpus outside the online stream. Forbidden in the release path. |

## Invariants

1. No pretrained weights, embeddings, tokenizer merges, or hidden checkpoints.
2. No offline pretraining or fine-tuning in the release path.
3. Every update records `input_stream`, `signal`, `rule`, `changed_tensors`, `checkpoint_sha256`.
4. **Online gradient learning is allowed in the mainline only as single-pass truncated backpropagation, fully logged.** *Amended 2026-11-26 by the written Gate A decision (`research/decisions/gate-a-2026-11-26.md`); until then online backpropagation was forbidden in the mainline.* Updates are driven by the chronological stream only (one pass, no replay of earlier bytes beyond the truncation window), never by a corpus outside the online stream, and each one is logged under invariant 3. Offline pretraining stays forbidden (invariant 2). Local rules (delta, e-prop) remain allowed as separate arms. Controls labelled CONTROL stay excluded from strict results.
5. Exposure, development, and hidden evaluation streams are separate. Hidden labels never reach the update controller. A stream used for online exposure is training input.
6. The model's own output is never a teacher.
7. Every accepted patch is versioned, attributable, reversible, and re-evaluated.
8. Self-modification never executes code, alters the runtime binary, CI, or protected evaluation data.
9. "Seven-year-old" / "twenty-year-old" are aspiration labels; report concrete capabilities.
10. Uniform execution (from the uniform-engine milestone on): content-dependent computation in the mainline model runs only through neural ISA (instruction set architecture: the fixed list of tensor operations in `docs/neural-isa.md`) operations on tensors; host code never branches on token content. Verified by an independent reference interpreter.
11. Compiled circuits (whose constants are the program weights) encode algorithms, never vocabulary, natural-language grammar, facts, or corpus statistics; each must pass the byte-permutation test.
12. Exposure text is human-written and licensed, listed in the corpus manifest with SHA-256; no text generated by any language model enters an exposure stream; benchmark items never appear in exposure.
13. The no-backpropagation rule (invariant 4) could change only through the written Gate A decision (`docs/roadmap.md` sec. 0.3 and 0.5, representation-feasibility milestone). It did, on 2026-11-26 (option (a)); any further change to invariant 4 needs a new written decision, never a silent edit.

## Bootstrap
<a name="bootstrap"></a>
Initial language: raw UTF-8 bytes (256 symbols). Permitted knowledge inventory is exactly the entries of `research/manifest/seed-knowledge.json`.

## Initialization
<a name="initialization"></a>
Weights start from `zeros`, a documented seeded PRNG, or a named seed entry. Every weight group in `model/specs/weight-groups.json` declares its `init_source` and `update_path`.

## Learning rules
<a name="learning-rules"></a>
Mainline learning is local plasticity (normalized delta rule), memory writes, and WSP patches. Constants are fixed in the online-learning spec and recorded as seed entries.

## CPU profiles
Reported per run: CPU model, cores, RAM, OS, Rust version; p50/p95 latency, tokens/s, peak RSS, checkpoint size, update cost. Targets are set by the architecture bake-off.
