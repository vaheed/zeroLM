# Changelog

## Unreleased

- **ZeroLM Next (research track, `research/`)**: an isolated, hand-weighted recurrent network that parses a bounded English instruction language compositionally (tensor-product binding, role-gated writes, time-ordered rows) into structured operations executed by a separate grid-world executor. New: `rust/src/next/`, `zerolm next ...` CLI (parse, run, trace, batch, repl, probe, info, ablations), `model/next/` (spec, patches, `weights.zln` generated by `research/build_next.py`), a seeded benchmark generator and evaluator, symbolic/keyword/lookup/random baselines, ablations, a weight-patch workflow (`research/tools/wsp.py`) with four documented manual patches, shortcut-detection tests (`rust/tests/next.rs`) and a `next` CI job. The v0.2 C runtime, Rust port, Live mode, HTTP API and Docker image are unchanged. See `research/README.md` and `research/RESULTS.md`.

- Added `docs/REPORT.md`, a measurement report (reading, writing, fixing and hardening the weights; accuracy against the number of phrases; CLINC150; runtime parity; speed; limits; why GGUF is not needed) and the experiment scripts behind it: `scripts/scaling_experiment.py`, `scripts/parity_fuzz.py` (C and Rust output diffed on 3,110 inputs including typo variants, also run in CI) and the earlier `robustness.py`. Raw results are in `reports/scaling.json` and `reports/heldout_test.json`; `reports/benchmarks.*` were re-run on the final weights.
- Phrases of one intent that are identical after stemming now count once, with the heaviest weight, in both runtimes; `build_model.py` warns about such duplicates. Found by reading `classify` output: stemming had let `test`/`tests`/`testing` triple-count. Cleaning 13 duplicates freed slots (506 features); held-out accuracy is now 87.7% (dev) and 83.7% (frozen test); CLINC150 in-scope accuracy 36.3%.
- Changed the example name in docs, tests and scripts from "Vahid" to "vaheeD".
- Added word-form tolerance to both runtimes, with identical results in C and Rust (checked on 1,715 prompts): light stemming of input and phrases, and spell-snapping of unknown words of six or more letters to the single phrase word one edit away. No weights changed for this; four inflected single-word phrases were replaced by multi-word ones (`installing`, `licensed`, `contributing`, bare `weights`) because stemming made them match their base words in unrelated questions. On corrupted prompts the answer now survives 85% of the time against 24% before (`scripts/robustness.py`); held-out accuracy is unchanged (dev 85.4%, test 82.9%) because the phrase families already covered word forms. The C model structure grows from 514 to 674 KiB.
- Widened the phrase coverage of the shipped model (281 to 510 features, same 28 intents and responses) and added two held-out prompt sets written before the change: `tests/heldout.tsv` (dev; 40.8% to 85.4%, 130 prompts) and `tests/heldout_test.tsv` (frozen; 43.9% to 82.9%, 123 prompts). The author of the model wrote both sets, so they are less independent than real user text. Existing regression (119/119) and unknown-input (31/31) tests are unchanged and still pass. CI fails if the held-out accuracy falls below 80% (dev) or 78% (test).
- Added intent-router tooling: `zerolm classify` (JSON lines with ranked intents and matched phrases), `POST /v1/classify` (single or batch, optional session reflexes), `build_model.py --spec/--out` for custom models, `scripts/evaluate_router.py` (accuracy, per-intent precision/recall, threshold sweep), the `examples/router/` sample, and `docs/ROUTER.md`.
- Added `zerolm serve`, an HTTP/JSON API (std only): an OpenAI-compatible `/v1/chat/completions` and `/v1/models` (models `zerolm`, stateless with the messages as context, and `zerolm-live`, a persistent session per `user`; streaming, `max_tokens`, OpenAI error envelope; tools/functions/`n>1` rejected) plus native `/v1/ask` and `/v1/sessions/{tag}` endpoints. Safe by default: loopback bind, token required elsewhere, request deadline, connection and session caps, shared life-file lock with the CLI. Contract in `rust/openapi.yaml` (validated in CI); docs in `docs/API.md`.
- Added a `zerolm-api` Docker Compose service with a health check (`zerolm health`), 20 API end-to-end tests, and a CI check with the official OpenAI Python SDK.
- Made the `privacy` answer precise about the optional API server (1,053 recurrent states, 515 vocabulary entries now).
- Grew the model from 18 to 28 intents (1,039 recurrent states at the time, 281 features): install, license, performance, languages, version, live, privacy, contribute, topics and comparison. Phrases are tied to ZeroLM ("install zerolm", "how fast is it") rather than bare words, and 13 near-miss prompts ("how do I install Photoshop") were added to the unknown tests. Regression is 119/119 and unknown abstention 31/31.
- Raised `MAX_FEATURES` to 512 and `MAX_VOCAB` to 1024 in the C runtime, Rust port and tools (model structure about 514 KiB).
- Added a std-only Rust port of the runtime (`rust/`) with output parity against the C binary, checked in CI. Bounded parsing replaces fixed C buffers; dangling state references are rejected at load time.
- Added `zerolm live` (ZeroLM Live): persistent decaying memory, rolling transcript for follow-ups, `teach` and good/bad feedback as a learned-reflex overlay, a `--jsonl` daemon mode, and `--tag NAME` sessions with life-file locking so sessions cannot overwrite each other. `weights.zlm` is never modified. See `docs/LIVE.md`.
- Added a Dockerfile and docker-compose.yml (multi-stage, about 117 MB, unprivileged, read-only, no network) with a `docker` CI job and `scripts/docker_smoke.sh`.
- Life files are locked with `flock`, which works across containers sharing a volume and needs no stale-lock handling. A first pid-file version was replaced because each container has its own pid namespace.
- Follow-up resolution now requires a cue word (`why`, `yes`, ...), so gibberish no longer repeats the previous answer.
- Added 16 end-to-end tests of `zerolm live` and `scripts/benchmark_all.py`, which records C vs Rust vs Live speed and memory in `reports/benchmarks.{json,md}`.
- Added `ZEROLM_MODEL` to set the default model path, a clippy CI step, and documentation for the whole project (`INSTALL.md` rewritten, `docs/CI.md` and `docs/LIVE.md` added).

## 0.2.0

- Made the prototype and documentation English-only.
- Expanded from 8 intent paths and 112 recurrent states to 18 intent paths and 694 states.
- Added a JSON model specification and deterministic serializer.
- Optimized the recurrent and output calculations using algebraically equivalent sparse operations.
- Added regression, unknown-input, graph-audit, report, and latency tools.
- Added a patch format and workflow inspired by Weight-Space Programming.
- Added GitHub Actions CI and full architecture/research documentation.
